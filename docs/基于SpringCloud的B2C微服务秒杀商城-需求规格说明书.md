# 1 引言

## 1.1 编写目的

本文档定义「基于 Spring Cloud 的 B2C 微服务秒杀商城」系统的业务范围、功能需求、数据需求、接口需求与非功能需求，作为系统设计、开发、测试、验收及后续维护的依据。

本文档面向：产品与需求人员、前后端开发人员、测试人员、运维部署人员。

## 1.2 项目背景

商城系统为 B2C（企业对消费者）模式：运营方在后台管理品牌、分类、商品、订单与权限；消费者（会员）在 PC 端完成浏览、检索、加购、下单、支付、收货的完整购物闭环，并支持限时限量的「秒杀」高并发场景。

系统由三部分组成：

- PC 商城前端（会员端）：面向会员的完整购物入口；
- 后台管理系统（管理端）：运营/管理人员的综合管理平台；
- 后端服务集群：以微服务架构支撑上述两端。

## 1.3 术语与缩略语

# 2 总体描述

## 2.1 产品定位与目标

建设一个面向生产环境的 B2C 商城，达成以下目标：

1. 提供完整购物流程：浏览 → 搜索/筛选 → 详情 → 加购 → 下单 → 支付 → 发货 → 收货；
2. 支持秒杀业务：限时限量抢购、防超卖、防刷、高并发下稳定可用；
3. 提供功能完整的后台管理系统：品牌、分类、商品、订单、会员、秒杀、RBAC 权限等全面管理；
4. 采用微服务架构，支撑服务独立部署与扩展，满足生产环境的稳定性与可维护性要求。

## 2.2 产品范围

### 2.2.1 系统构成

| 子系统 | 使用者 | 说明 |
| --- | --- | --- |
| PC 商城前端（前台） | 会员、游客 | 商品浏览、购物车、下单支付、个人中心 |
| 后台管理系统（管理端） | 后台运营/管理人员 | 商品、订单、会员、秒杀、系统权限等管理 |
| 后端服务集群 | — | 以微服务形式提供业务能力支撑 |

### 2.2.2 不在范围内

- 商品 SKU/规格体系：商品以单品（SPU）管理，不含多规格；
- 移动端 App / 小程序：本期仅提供 PC 商城前端，移动端不做；
- 真实支付渠道：支付与退款均以模拟方式实现，不接入支付宝/微信等真实渠道。

注：物流仅记录发货时间与状态，不接入物流商轨迹。

## 2.3 业务角色

| 角色 | 归属子系统 | 职责 |
| --- | --- | --- |
| 游客 | 前台 | 浏览、搜索、查看商品详情（不可下单） |
| 会员 | 前台 | 注册、登录、购物、下单、支付、收货、管理个人资料与地址 |
| 超级管理员 | 后台 | 系统初始化、权限配置、全部功能 |
| 运营人员 | 后台 | 品牌、分类、商品、秒杀内容运营 |
| 订单管理员 | 后台 | 订单查询、发货、取消、退款处理 |
| 系统管理员 | 后台 | 后台用户、角色、权限、菜单、用户组管理 |

注：后台角色权限通过 RBAC 动态配置，不限于上表固定划分。

## 2.4 运行环境

| 环境 | 要求 |
| --- | --- |
| 客户端浏览器 | Chrome / Edge 主流版本，分辨率 1920*1080 及以上 |
| 数据库 | MySQL 9.2.7 |
| 缓存 | Redis |
| 消息队列 | RabbitMQ |
| 服务注册/配置中心 | Nacos |
| 部署方式 | 后端服务集群支持容器化部署；前端静态资源经 Nginx 托管并反代网关 |

## 2.5 设计与实现约束

1. 后端采用 Spring Cloud + Spring Cloud Alibaba 微服务技术栈；
2. 持久层使用 MyBatis，不采用 MyBatis-Plus；
3. 消息队列采用 RabbitMQ；
4. 后台管理系统前端采用 Vue3 + Element Plus + JavaScript + Axios；
5. PC 商城前端为会员端商城，前端技术栈与后台一致（Vue3 + Axios）；
6. 前后端接口采用 JSON 数据格式与统一响应结构（见 8.1）；
7. 所有业务写操作记录审计信息（操作人、时间）。

## 2.6 假设与依赖

1. 支付以模拟方式实现（不接入真实支付渠道），退款同样以模拟方式实现；如需接入真实支付渠道（如微信支付）需另行确认；
2. 秒杀依赖缓存与消息队列的高可用；
3. 图片等静态文件统一经文件服务管理；
4. 行政区划数据来源于民政部标准数据，系统提供维护能力。

# 3 系统总体要求

## 3.1 系统构成与逻辑分层

系统在逻辑上自顶向下分为三层：

- 表现层：PC 商城前端、后台管理系统两个 Web 应用；
- 服务层：按业务域拆分、可独立部署的后端服务集群，通过统一网关对外提供接口；
- 数据层：关系数据库、缓存、消息队列、文件存储等基础设施。

## 3.2 业务功能域划分

系统按业务域划分功能模块，各域职责如下（模块化划分要求，便于服务化实现）：

| 业务域 | 主要职责 |
| --- | --- |
| 商品中心 | 品牌、分类、商品、商品图片与富文本详情 |
| 交易中心 | 购物车、订单、订单明细、支付 |
| 会员中心 | 会员资料、收货地址 |
| 秒杀中心 | 秒杀活动、秒杀商品、抢购 |
| 权限中心 | 后台用户、RBAC 权限、动态菜单 |
| 基础数据 | 行政区划 |
| 文件服务 | 图片等静态文件的上传与访问 |
| 系统支撑 | 统一网关、认证鉴权、配置与注册中心 |

## 3.3 认证与权限总体要求

1. 系统须区分会员身份与后台用户身份，分别提供登录认证；
2. 登录成功签发令牌，后续请求携带令牌进行身份校验；
3. 后台功能按 RBAC 控制：用户 → 用户组 → 角色 → 权限 → 资源（接口/按钮），未授权访问须拒绝；
4. 后台菜单须按当前用户权限动态展示；
5. 会员只能访问本人的购物车、订单、地址等数据；
6. 密码须加密存储（不可逆加密），禁止明文。

## 3.4 接口与数据格式总体要求

1. 前后端接口统一使用 JSON；
2. 统一响应结构：状态码、成功标志、消息、业务数据；业务失败与系统错误须有明确区分；
3. 列表查询须支持分页，并提供统一的请求/响应分页约定；
4. 统一错误码约定：未登录、无权限、参数错误、资源不存在、系统错误、业务错误等须可区分。

## 3.5 集成需求

1. 支付：以模拟方式实现支付发起与结果确认，并支持退款模拟；
2. 文件：支持图片上传（品牌 Logo、商品主图/次图/详情图、会员头像），上传后返回可访问 URL；
3. 行政区划：提供省市区三级数据及维护能力，供收货地址、会员籍贯等使用。

# 4 数据需求

## 4.1 数据对象总览（DR-001）

数据对象依据数据库脚本梳理，共 22 个（不含未采用的 SKU/规格体系），按业务域划分如下：

| 业务域 | 数据对象 |
| --- | --- |
| 商品中心 | 品牌、分类、商品（SPU）、商品详情图片 |
| 交易中心 | 购物车、订单、订单明细 |
| 会员中心 | 会员、会员收货地址 |
| 秒杀中心 | 秒杀活动、秒杀活动商品 |
| 基础数据 | 行政区划 |
| 权限中心 | 后台用户、用户组、角色、权限、资源、菜单，以及 组-角色、角色-权限、权限-资源、用户-组 关联关系 |

## 4.2 关键数据对象与属性

### 4.2.1 品牌

名称、公司名称、Logo、网址、简介，以及审计信息（创建/修改人、时间）。

### 4.2.2 分类

支持多级树形结构：父分类、名称、标题、标签、图标、摘要、排序、简介。

### 4.2.3 商品

- 基本：货号（唯一）、名称、别名、摘要、所属分类、所属品牌；
- 价格库存：标价、实价、库存；
- 展示：主图、次图、详情图、富文本详情；
- 状态：上架/下架、热销标识、是否秒杀商品、逻辑删除、备注；
- 审计信息。

### 4.2.4 商品详情图片

所属商品、图片 URL、排序、说明。

### 4.2.5 购物车

所属会员、商品、数量。

### 4.2.6 会员

- 账号（唯一）、密码（加密存储）、启用状态；
- 资料：姓名（含拼音）、性别、生日、身高/体重、手机、邮箱、QQ、微信、头像、籍贯（地区）、证件号、婚姻状况、政治面貌、民族/宗教/国籍等；
- 扩展信息（结构化/JSON）与并发控制版本号；
- 登录信息：最近登录时间、最近登录 IP。

### 4.2.7 会员收货地址

所属会员、收货人、手机号、所在地区（省市区）、详细地址、是否默认地址。

### 4.2.8 订单

- 订单号（全局唯一）、秒杀流水号（秒杀订单填写）、下单会员账号；
- 金额与支付：应付总额、支付方式、支付交易号、下单/支付/发货/收货时间；
- 状态（见 4.4）；
- 收货人快照（下单时复制地址，防止地址变更影响历史订单）；
- 订单备注、逻辑删除、审计信息。

### 4.2.9 订单明细

所属订单、商品、成交价、数量，以及商品名称/图片/描述快照（防止商品变更影响历史订单展示）。

### 4.2.10 秒杀活动

名称、启用状态、开始时间、结束时间、说明。

### 4.2.11 秒杀活动商品

活动、参与商品、秒杀价、秒杀库存、已售数量、每人限购数、说明。

### 4.2.12 行政区划

名称、父级、排序、层级（省/市/区）。

### 4.2.13 后台用户

用户名（唯一）、密码（加密）、头像、账号状态、启用/锁定状态、账号/凭证过期时间、登录次数、最近登录时间与 IP、操作模式。

### 4.2.14 RBAC 数据对象

- 用户组：名称、启用状态、说明；
- 角色：名称、启用状态、说明；
- 权限：名称、启用状态、说明；
- 资源：名称、类型（接口/按钮）、值（路径或按钮标识）、说明；
- 菜单：父级、名称、图标、URL、排序、关联资源；
- 关联关系：用户-组、组-角色、角色-权限、权限-资源。

## 4.3 数据关系与约束（DR-002）

1. 商品关联分类、品牌；分类支持多级树形；
2. 订单与订单明细为一对多；订单明细冗余商品信息快照；
3. 订单与会员关联，同时保存收货人快照，历史订单不受地址与商品变更影响；
4. 订单与秒杀活动商品通过秒杀流水号关联；
5. 购物车、收货地址、订单归属单一会员；
6. 金额字段使用定点数（decimal），禁止浮点数；
7. 商品、订单等支持逻辑删除，删除数据不可在前台展示；
8. 关键外键字段（商品-分类/品牌、订单-会员、明细-订单等）须建索引以保证查询性能。

## 4.4 关键字典（DR-003）

订单状态（生命周期：待付款 → 已支付 → 待收货 → 已确认；另有已取消）：

| 状态 | 含义 | 可执行操作 |
| --- | --- | --- |
| 待付款 | 已下单未支付 | 支付、取消（超时自动关闭） |
| 已支付 | 已支付待发货 | 后台发货、退款申请 |
| 待收货 | 已发货待收货 | 确认收货 |
| 已确认 | 已确认收货（完成） | 查看 |
| 已取消 | 已取消 | 查看 |

支付方式：模拟支付（不接入真实支付渠道）。

退款状态：无 / 退款中 / 已退款（模拟退款记录）。

商品状态：上架 / 下架 / 逻辑删除；秒杀标识：是否秒杀商品。

秒杀活动状态：由启用状态与起止时间推导：未开始 / 进行中 / 已结束 / 已禁用。

## 5.2 会员注册与登录（FR-101）

- 注册：账号（手机号或用户名，唯一校验）、密码（两次确认、强度校验）；注册成功自动登录或跳转登录；
- 登录：账号 + 密码校验、记住登录状态；成功后保存登录令牌；
- 退出登录：清除令牌并跳转首页；
- 游客访问受保护页面（购物车、下单、个人中心）时跳转登录，登录后回跳原页面；
- 表单校验：账号格式、密码强度、必填项即时校验。

## 5.3 首页（FR-102）

- 顶部导航：Logo、搜索框、购物车入口（角标数量）、登录/会员入口、个人中心入口；
- 轮播 Banner（可配置图片与跳转链接）；
- 分类导航（一级分类快捷入口）；
- 推荐/热销商品区（热销且上架商品）；
- 秒杀入口：展示进行中秒杀活动与倒计时（P1）；
- 底部：版权、客服等静态区。

## 5.4 商品列表页（FR-103）

- 入口：分类下钻、关键字搜索、品牌筛选；
- 筛选条件：分类、品牌、价格区间；
- 排序：默认（最新）、价格升/降、热销；
- 商品卡片：主图、名称、实价（含标价）、热销标识；
- 分页展示；
- 仅展示上架且未删除商品；空结果显示空态提示；
- 页面刷新后保留筛选与分页状态。

## 5.5 商品详情页（FR-104）

- 商品信息：图片轮播（主图/次图/详情图）、名称、摘要、实价与标价、库存、品牌、分类；
- 数量选择：加减与输入，上限为库存；
- 操作：加入购物车、立即购买（直达订单确认）；
- 详情区：富文本详情与详情图；
- 下架/删除商品：访问提示并回列表；
- 库存不足：禁用购买并提示；
- 秒杀商品：展示秒杀价与活动倒计时，按钮为「立即秒杀」（P1，见 5.9）。

## 5.6 购物车（FR-105）

- 展示：商品图、名称、单价、数量、小计；
- 操作：修改数量（校验库存上限）、删除单项/批量删除、勾选/全选；
- 结算栏：已选数量、合计金额（仅统计勾选项）、去结算；
- 仅当前登录会员可见本人购物车；
- 空购物车提示与「去逛逛」入口。

## 5.7 结算与订单支付（FR-106）

### 5.7.1 订单确认

- 来源：购物车勾选项批量下单、商品详情「立即购买」单件下单、秒杀（5.9）；
- 收货地址：默认地址预选，可切换/新增；
- 商品清单：下单时固化商品快照，结算页不可改动；
- 金额合计、订单备注；
- 提交订单：生成订单（待付款）、扣减库存，库存不足提示失败；防止重复提交。

### 5.7.2 支付

- 支付方式：模拟支付（不接入真实支付渠道）；
- 发起支付进入模拟收银台，确认支付后跳转支付结果页；
- 支付成功后订单变为「已支付」，展示支付交易信息；
- 待付款订单超时未支付自动关闭并释放库存（见 7.4）。

### 5.7.3 订单状态流转

```
待付款 ──支付──▶ 已支付 ──后台发货──▶ 待收货 ──确认收货──▶ 已确认
   │
   ├──取消──▶ 已取消
   └──超时自动关闭──▶ 已取消
```

## 5.8 个人中心（FR-107 / FR-108 / FR-109）

个人中心导航：个人信息、收货地址、我的订单、安全设置（修改密码，P2）。所有操作仅限当前登录会员本人数据。

### 5.8.1 个人信息（FR-107）

- 查看：账号、姓名、性别、生日、手机、邮箱、QQ、微信、头像等；
- 编辑：修改可编辑字段并保存；
- 修改密码：旧密码校验 + 新密码强度校验（P1）；
- 头像上传。

### 5.8.2 收货地址管理（FR-108）

- 列表：收货人、手机号、地址、默认标识，支持编辑/删除；
- 新增/编辑：省市区三级联动选择 + 详细地址，收货人、手机号格式校验，可设为默认；
- 默认地址：仅允许一个默认地址；
- 删除前确认；默认地址删除后需重新指定。

### 5.8.3 我的订单（FR-109）

- 订单列表：按状态筛选（全部/待付款/已支付/待收货/已确认/已取消），展示订单号、商品缩略、金额、状态、下单时间，分页；
- 订单详情：订单号与各状态时间、收货人快照、商品明细、金额、备注；
- 取消订单：仅待付款可取消，取消后恢复库存；
- 确认收货：仅待收货可操作，确认后状态变更为「已确认」；
- 删除订单（P2）：逻辑删除。

## 5.9 秒杀功能（FR-110，P1）

- 秒杀会场：展示秒杀活动（进行中/即将开始），含倒计时与活动说明；
- 秒杀商品：秒杀价、原价、剩余库存、每人限购提示；
- 抢购流程：
  1. 会员登录后点击「立即秒杀」；
  2. 校验活动时间窗与启用状态、限购次数；
  3. 抢购成功 → 生成秒杀订单（关联秒杀流水号）→ 进入支付流程；
  4. 售罄/已参与 → 明确提示；
- 防重复提交（按钮置灰、防抖）；
- 已抢购未支付：展示支付倒计时，超时（30 分钟，与普通订单一致）未支付释放名额。

# 7 业务规则

## 7.1 库存与下单（FR-301）

1. 普通下单：事务内扣减商品库存，库存不足时扣减失败、下单失败；
2. 订单号全局唯一（支持高并发生成）；
3. 下单须校验商品为上架未删除状态；
4. 取消订单、超时关闭订单须回补库存。

## 7.2 订单状态机（FR-302）

1. 订单状态流转必须遵循 4.4 状态机，非法流转拒绝；
2. 仅待付款订单可取消；仅待收货订单可确认收货；仅已支付订单可发货；
3. 会员只能操作本人订单；后台按权限操作。

## 7.3 秒杀业务规则（FR-303，P0 级别重点）

1. 仅活动时间窗内（且启用）可抢购，提前/延后请求一律拒绝；
2. 必须防超卖：并发抢购下成交数量不得超过秒杀库存；
3. 每人限购：同一会员对同一秒杀商品限购一次（限购数可配置）；
4. 秒杀下单异步处理，抢购结果及时反馈（提交后返回，结果可查询）；
5. 秒杀订单超时未支付（30 分钟，与普通订单一致）自动关闭后，名额/库存回补；
6. 防刷：对同一账号/IP 的高频请求限流。

## 7.4 数据一致性（FR-304）

1. 涉及多步写入的业务（如下单）须保证数据一致，失败可回滚或补偿；
2. 支付结果确认、异步消息处理须幂等，重复通知不产生重复数据；
3. 待付款订单超时自动关闭（默认 30 分钟，可配置）并释放库存；
4. 库存、订单、支付结果之间最终一致。

## 7.5 审计与权限边界（FR-305）

1. 所有写操作记录操作人与时间；
2. 会员数据严格归属校验，禁止越权访问他人数据；
3. 后台敏感操作（删除、发货、退款、权限变更）须记录审计信息（P1）。

# 9 非功能需求

## 9.1 性能需求（NFR-001）

| 场景 | 目标 |
| --- | --- |

## 9.2 安全需求（NFR-002）

- 认证：登录令牌有效期——管理员 12 小时、会员 7 天（可配置），并支持刷新；
- 密码：不可逆加密存储；后台用户支持锁定与账号/凭证过期策略；
- 授权：后台接口/菜单/按钮按 RBAC 校验；会员数据严格归属校验；
- 传输：生产环境全站 HTTPS；敏感字段（手机号、证件号）脱敏展示（P2）；
- 防护：SQL 注入防护、XSS 过滤、文件上传类型/大小校验；
- 防刷：登录失败限流、秒杀抢购限流、验证码（P1）；
- 审计：登录日志、敏感操作审计（P1）；
- 支付安全：模拟支付须校验订单与金额一致性，防止伪造支付结果。

## 9.3 可用性与可靠性（NFR-003）

- 关键服务多实例部署，故障自动剔除与降级；
- 数据库主从/备份，每日备份；
- 消息消费失败重试与死信处理，保证最终一致；
- 秒杀活动数据未就绪时不开始活动（兜底开关）。

## 9.4 可维护性与可扩展性（NFR-004）

- 按业务域模块化划分，新增业务不影响既有模块；
- 统一日志与链路追踪，支持问题排查（P1）；
- 服务健康检查；生产建议接入监控告警（P2）；
- 配置按环境隔离管理。

## 9.5 兼容性（NFR-005）

- 浏览器：Chrome / Edge 主流版本；
- 前端构建产物经 Nginx 静态托管。

## 9.6 数据保留与合规（NFR-006）

- 订单数据长期保留，支持归档；会员注销（P2）；
- 遵守个人信息保护要求，会员可查看/更正个人资料，收集最小化；
- 金额与财务数据不可逆删除，仅允许状态标记。
