# 秒杀模块实现与启动

## 首次使用

1. 已有数据库执行 `sql/seckill-migration.sql`。全新数据库使用更新后的 `sql/flashchoice-mart.sql`。迁移脚本最后一条唯一索引只执行一次；已有同名索引时跳过该条。
2. 确认本机的 MySQL、Nacos、Redis、RabbitMQ 已按原配置初始化，Nacos 的 `common.yaml` 数据源配置可用；安装 JDK 25 与 Node.js。脚本使用本机现有的 `D:\MySQL`、`D:\Nacos`、`D:\Redis`、`D:\RabbitMQ` 安装目录，可通过 PowerShell 参数覆盖路径。本机 RabbitMQ 4.3.5 与原有 Erlang 29 不兼容，脚本优先使用项目 `.local/erlang27` 中的官方便携版 Erlang 27；该目录已在本机准备好且被 Git 忽略。
3. 双击项目根目录 `start-project.bat`。脚本依次启动尚未运行的 MySQL、Redis、RabbitMQ、Nacos，然后构建并启动所有微服务、网关及 `../FlashChoiceMart-frontend/mall-web`，将日志写入 `runlogs/`。再次启动可传 `-SkipBuild` 复用现有 jar；`-DryRun` 只预览中间件命令；`-SkipInfra` 跳过中间件启动。前端地址为 <http://localhost:5173>。

## 抢购流程

会员在秒杀会场选择收货地址后提交。Redis Lua 原子扣减库存并计入限购；抢购流水保存到 `seckill_grab`，RabbitMQ 消费者对秒杀商品进行数据库条件扣减，随后在订单服务按秒杀价格生成待付款订单。前端根据流水号轮询结果，成功后在「我的订单」支付。订单取消或 30 分钟未付款自动关闭时回补商品及秒杀库存；秒杀服务每分钟扫描已取消但未回补的流水进行修复。处理中流水会定时重投消息，订单以唯一 `seckill_no` 保证幂等。

## 验证与限制

后端可用 `./mvnw.cmd -DskipTests package` 构建，前端在 `mall-web` 内用 `npm run build` 验证。已通过脚本实际启动全部组件，并验证商城首页与 `GET /api/seckills/active` 均返回 HTTP 200；尚未进行真实抢购或并发压测。发布到多实例环境前，应配置 RabbitMQ 发布确认及独立的服务实例身份，并开展并发与故障恢复测试。
